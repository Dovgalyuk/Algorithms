# Лабораторная работа 1. Динамический массив

Решение на C++11: контейнер `Array<Data>` и две программы обработки массива.

## Контейнер

Файл: `LibraryCPPTemplate/array.h`.

Память выделяется динамически при создании массива. Размер не меняется.
`std::unique_ptr<Data[]>` освобождает выделенную память при уничтожении объекта.
Это собственный контейнер, `std::vector` не используется.

Методы: `size()`, `get(index)`, `set(index, value)`. Копирование создаёт
независимый массив. Присваивание разрешено только для массивов одинакового
размера; иначе возникает `std::length_error`. Неверный индекс вызывает
`std::out_of_range`. Числовые элементы изначально равны нулю.

## Осадки по месяцам

Программа `Lab1CPPMonthly` читает имя входного файла из командной строки.
В файле сначала записано количество дней: 365 или 366, затем столько же
неотрицательных чисел — осадки за каждый день с 1 января.
При 366 днях в феврале 29 дней. Дробная часть отделяется точкой.

Вывод: 12 сумм в одной строке, от января до декабря.

Пример запуска из корня проекта в PowerShell:

```powershell
.\build\Lab1CPP\Debug\Lab1CPPMonthly.exe .\Lab1CPP\examples\monthly_constant.txt
```

Результат для одного миллиметра осадков ежедневно в обычном году:

```text
31 28 31 30 31 30 31 31 30 31 30 31
```

## Сжатие массива

Программа `Lab1CPPCompress` читает из файла количество элементов `n >= 0`,
затем `n` чисел, затем границы интервала `a b`. Границы вводятся в том же файле,
должно выполняться `a <= b`.

Все элементы из замкнутого интервала `[a, b]`, включая границы, удаляются.
Остальные сохраняют порядок. Освободившиеся позиции заполняются нулями;
размер массива остаётся прежним. Пустой массив даёт пустую строку.

Пример файла:

```text
8
1 2 3 4 5 6 2 -1
2 4
```

Запуск:

```powershell
.\build\Lab1CPP\Debug\Lab1CPPCompress.exe .\Lab1CPP\examples\compress_mixed.txt
```

Результат:

```text
1 5 6 -1 0 0 0 0
```

Обе программы выводят результат в консоль, ошибки — в stderr и возвращают
ненулевой код. Сжатие выполняется за O(n), без второго массива.
Для осадков время O(n), дополнительная память — массив из 12 сумм.

## Сборка и тесты

Выполнять из корня репозитория, где находятся `CMakeLists.txt` и `LibraryCPPTemplate`.
На Windows нужны CMake и Visual Studio 2022 с компонентом
«Разработка классических приложений на C++».

```powershell
cmake -S . -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config Debug
ctest --test-dir build -C Debug --output-on-failure
```

Linux с установленными CMake и g++:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build
ctest --test-dir build --output-on-failure
```

В стандартной сборке 28 тестов:

* Исходный `TestArrayCPPTemplate` из репозитория преподавателя без изменений.
* Дополнительная проверка контейнера: копирование, присваивание,
  неизменность размера, пустой массив, границы индексов, строки.
* Пять примеров осадков: обычный и високосный год, последовательные значения,
  дробные значения, отсутствие осадков.
* Семь примеров сжатия: частичное удаление, удаление всех элементов,
  отсутствие удалений, одинаковые границы, пустой массив, дробные значения,
  единственный элемент.
* Четырнадцать проверок ошибок: неверные размеры и значения, неполные данные,
  отрицательные осадки, переполнение суммы, обратный интервал,
  отсутствие границ, отсутствие файла и аргументов.

Для правильных входных данных `check_output.cmake` сравнивает полный stdout
с файлом `.expected`, учитывая различия переносов строк Windows/Linux.
Проверяется также код завершения программы.
Для неверных данных CTest требует ненулевой код завершения.

`monthly_missing.txt` и `compress_missing.txt` намеренно отсутствуют:
соответствующие тесты проверяют ошибку открытия файла.

Остальные шаблоны исходного репозитория сохранены. Незавершённые `LibraryC`,
`LibraryCPP`, `LibraryCPPClass` и `Lab1C` подключаются опцией
`-DBUILD_STARTER_EXAMPLES=ON`. Они не относятся к этой реализации; их тесты
и сборка могут падать, пока заглушки не реализованы. По умолчанию опция
выключена, собирается и проверяется лабораторная на C++.
