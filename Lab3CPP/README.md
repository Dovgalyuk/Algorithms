# Лабораторная работа 3: недостижимые клетки лабиринта

## Задание

Реализовать в `LibraryCPP` динамический массив (`vector`) и очередь (`queue`)
на его основе. Очередь должна использовать расширяемый кольцевой буфер.
С помощью собственной очереди найти клетки лабиринта, недостижимые из самой
левой клетки. Переход разрешён только в соседнюю клетку с числом на 1 больше
или на 1 меньше текущего. Недостижимые числа заменяются на `#`.

## Сборка, запуск и тестирование

Из корня репозитория:

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=RelWithDebInfo
cmake --build build -j 4
./build/Lab3CPP/Maze Lab3CPP/test_data/example.txt
ctest --test-dir build --output-on-failure
```

Программа принимает путь к одному входному файлу. Выводит результат в stdout,
ошибки — в stderr, код завершения при ошибке равен 1.
Пример преподавателя сохранён в `test_data/example.txt`, точный ожидаемый
вывод — в `test_data/example.expected`.

## Представление лабиринта

Числа разделены пробельными символами; одна непустая строка файла соответствует
одной строке клеток. Строки логически выравниваются по центру самой широкой
строки. В примере количество клеток в строках — 1, 3, 5, 7, 5, 3, 1.
Соседи находятся слева, справа, сверху и снизу; диагональные переходы отсутствуют.
Горизонтальные отступы в файле нужны для отображения, координаты вычисляются
по количеству клеток. Разность длин строк должна быть чётной для выравнивания
на общей сетке. Такой способ позволяет читать и отрицательные, и многозначные
целые числа без зависимости от ширины их записи.

Старт — первая клетка строки с минимальным левым отступом на логической сетке.
В ромбе из задания это единственная крайняя левая клетка средней строки.
Если крайних левых клеток несколько, выбирается верхняя из них.

Пробелы и пустые строки исходного файла сохраняются. Пустые строки не образуют
ряды клеток. Для многозначного недостижимого числа выводится `#` и пробелы до
ширины исходной записи. Окончания строк CRLF преобразуются в LF; последняя
выводимая строка завершается переводом строки даже при его отсутствии во входе.
Допустимы значения типа `int`; сравнение соседних значений выполняется через
`long long`, чтобы избежать переполнения на границах диапазона.

## Реализация контейнеров

`LibraryCPP/vector.cpp` хранит указатель на массив, логический размер и ёмкость.
При нехватке ёмкости она удваивается до достаточного значения. Уменьшение
логического размера не освобождает резерв; новые элементы получают ноль.
Последовательное увеличение размера на один имеет амортизированную сложность
O(1). Произвольное увеличение на много элементов требует их инициализации.
Выход за логический размер вызывает `std::out_of_range`, переполнение размера —
`std::length_error`.

`LibraryCPP/queue.cpp` хранит собственный `Vector`, индекс первого элемента и
число элементов. Размер вектора соответствует числу доступных слотов буфера.
Добавление записывает элемент по индексу `(first + size) % capacity`, удаление
сдвигает только индекс начала. При заполнении вектор увеличивается вдвое.
Если содержимое пересекало границу массива, его начальный участок переносится
в новую половину буфера, сохраняя порядок FIFO. Сдвиг всех элементов при каждом
удалении отсутствует. Добавление занимает O(1) амортизированно, чтение и удаление
— O(1). Ограничения фиксированной ёмкости нет; размер ограничен доступной памятью.
Чтение и удаление из пустой очереди вызывают `std::out_of_range`.

## Решение задачи

`maze.cpp` выполняет обход в ширину через функции `queue_insert`, `queue_get`,
`queue_remove`, `queue_empty` из `LibraryCPP`. В очередь помещаются индексы
клеток; клетка отмечается достигнутой при добавлении, поэтому повторных
добавлений нет. Для каждого из четырёх соседей проверяется разность значений
+1 или -1. После обхода недостигнутые клетки заменяются на `#`.
Для N клеток обход занимает O(N) времени и O(N) дополнительной памяти.
Стандартные контейнеры используются для хранения карты и текста; рабочая
очередь обхода реализована через собственные модули `queue` и `vector`.

## Проверки

Исходники тестов преподавателя `LibraryCPP/Tests/vector.cpp` и `queue.cpp`
не изменены; их запуск включён в CMake. Каждый содержит проверку на 10000000
элементов. `tests/containers.cpp` отдельно проверяет сохранение данных вектора,
уменьшение и повторное увеличение размера, нулевые новые элементы, ошибки
индексов и размера, пустую очередь, расширение после перехода через конец
буфера, FIFO для 100000 значений, 200000 смешанных операций в сравнении с
`std::deque` и повторные обороты буфера.

В `CMakeLists.txt` зарегистрированы 15 тестов программы:

| Тест | Проверка |
| --- | --- |
| `example` | Точное совпадение с примером преподавателя |
| `single` | Единственная клетка |
| `connected` | Все клетки достижимы, есть переходы +1 и -1 |
| `isolated` | Достижима только стартовая клетка |
| `equal_values` | Равенство значений не разрешает переход |
| `no_diagonals` | Диагональное соседство не разрешает переход |
| `leftmost_start` | Начало обхода в самой левой клетке, а не в верхней |
| `signed_values` | Отрицательные и положительные числа |
| `integer_limits` | Границы int, отсутствие переполнения и ширина маркера |
| `crlf` | Вход с окончаниями строк Windows |
| `no_final_newline` | Вход без завершающего перевода строки |
| `wide_frontier` | Ромб из 3281 клетки с широким фронтом обхода |
| `empty` | Диагностика пустого лабиринта |
| `invalid_value` | Диагностика неверной записи числа |
| `invalid_alignment` | Диагностика несовместимых длин строк |

`cmake/RunAndCompare.cmake` запускает исполняемый файл с входными данными,
проверяет код завершения и stderr, затем сравнивает stdout с эталоном,
включая пробелы и переводы строк.
