Лабораторная работа 5. Сравнение вставки строк
Давлатов, группа 5093

Условия измерения
Дата: 11.11.2026.
Процессор: AMD Ryzen 7 5825U. ОС: Windows 11 Pro, 10.0.26200.
Компилятор: MSVC 19.39.33523, x64, Release (/O2, NDEBUG), C++17.
Размеры: 1000, 5000, 10000, 25000, 50000, 100000, 250000,
500000, 1000000 и 2000000 строк.
Каждая строка содержит уникальное значение длиной 13 символов.
Исследованы возрастающий, убывающий и случайный порядки.
Для перемешивания используется mt19937 с начальным значением 5093.
В каждой точке берётся медиана трёх запусков на новых пустых контейнерах.
Порядок измерения контейнеров меняется между запусками.
Файл читается в vector<string> до измерения. Всем трём контейнерам
передаются одинаковые строки. Таймер охватывает только цикл вставки.
Создание контейнера, чтение файла, проверка результата и освобождение
памяти не входят в замер. Для unordered_set не вызывается reserve.

Результаты для 1000000 строк, миллисекунды
Порядок             АВЛ          std::set     std::unordered_set
По возрастанию      719.064      495.804      389.647
По убыванию         488.152      532.467      380.802
Случайный          1816.157     1482.960      500.155

Вывод
У АВЛ-дерева высота поддерживается порядка log(N), поэтому вставка,
поиск и удаление одного значения требуют O(log(N)) сравнений.
Вставка N строк в АВЛ и std::set имеет зависимость O(N * log(N)).
У std::unordered_set ожидаемая стоимость вставки N строк — O(N),
но это средняя оценка: неблагоприятные коллизии могут ухудшить её.
Эти оценки считают длину строки постоянной, как в наших данных.

На этих измерениях unordered_set оказался быстрее обоих деревьев.
Случайный порядок в этих замерах особенно замедляет деревья.
Возможная причина — изменение путей обхода и работы кеша памяти.
Разница констант также зависит от реализации контейнера.
При удвоении больших объёмов время не растёт
в четыре раза, характерные для квадратичной зависимости.
Графики не доказывают сложность сами по себе. Дополнительно тесты
проверяют высоты, баланс всех узлов, порядок и миллион операций
каждого вида. Ограничение времени CTest выявляет резкое замедление.

insertion_time.png показывает время вставки.
normalized_time.png показывает T / (N * log2(N)) для деревьев
и T / N для unordered_set. Из-за кеша и выделения памяти эти линии
не обязаны быть строго горизонтальными.

Воспроизведение из корня проекта в PowerShell
cmake -S . -B build
cmake --build build --config Release --target TestAVLCPP Lab5CPPGenerate Lab5CPPStress Lab5CPPBenchmark
ctest --test-dir build -C Release -R '^(TestAVLCPP|TestLab5)' --output-on-failure --no-tests=error

Для каждого порядка ascending, descending и random:
.\build\Lab5CPP\Release\Lab5CPPGenerate.exe .\build\Lab5CPP\data.txt 2000000 ascending
.\build\Lab5CPP\Release\Lab5CPPBenchmark.exe .\build\Lab5CPP\data.txt .\Lab5CPP\results\ascending.csv 3
В двух командах заменить ascending на нужный порядок.

python .\Lab5CPP\plot.py
